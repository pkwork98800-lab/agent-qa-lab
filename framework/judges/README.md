# framework/judges — judges + calibration kit (agent 5)

## What it does

This module separates the portfolio: a rubric with anchored 1–5 scales, three
judges behind one interface, and a calibration report with real Cohen's kappa
against human labels.

It exports the frozen surface from `docs/BUILD-CONTRACT.md` §7:

- `getJudge(id)` — `'mock' | 'claude' | 'openai'`
- `computeKappa(a, b)` — Cohen's kappa over two label sequences
- `confusionMatrix(labels, preds, classes)` — rows = human, cols = judge
- `calibrate(opts)` — run the mock judge over golden answers vs human labels,
  write `reports/judge-calibration.md`

## Judges

- **mock** (`mock-judge.ts`): deterministic, no network, no API keys. Scores
  `groundedness`, `task-completeness`, `tone-policy`, `safety` from the
  request's grounding (`toolsCalled` + `dbDiff`) and the expected outcome, using
  explicit named rules. `overall = min(dimensions)`. Rationale names the
  dimension and rule that fired. This is what `calibrate()` measures.
- **claude**: Anthropic Messages API (live), rubric as system prompt, JSON-only
  response, temperature 0, retry/backoff, cost metering, content-hash caching.
  Throws via `requireLiveKey` without `ANTHROPIC_API_KEY`.
- **openai**: OpenAI Chat Completions (live), same contract. Throws without
  `OPENAI_API_KEY`.

Live judges are cached by `contentHash({scenarioId, answer, rubricId, model})`
in `cache.ts`, so re-runs are free.

## How to run alone

```bash
# 1. Generate 60 genuine agent answers from runChat against a booted app
npx tsx framework/judges/golden-set/build.ts

# 2. Run calibration: mock judge vs the 12-entry pilot human labels
npx tsx framework/judges/calibrate.ts
```

This writes `framework/judges/golden-set/golden-answers.jsonl` (60 entries)
and `reports/judge-calibration.md` (confusion matrix, accuracy,
precision/recall on `fail`, Cohen's kappa, per-dimension breakdown, cost per
1,000 judgements, bias probes).

## Inputs

| File | What it is |
|---|---|
| `scenarios/core/*.json` | 30 real scenarios the golden set is built over |
| `framework/judges/golden-set/golden-answers.jsonl` | 60 genuine answers (generated by `build.ts`) |
| `framework/judges/golden-set/human-labels.jsonl` | 12 PILOT human labels (replace with the full 60-entry pass) |
| `framework/judges/fixtures/recorded-verdicts.fixture.json` | 10 fixture verdicts proving adapter/caching/cost paths |

## Outputs

| File | What it is |
|---|---|
| `framework/judges/golden-set/golden-answers.jsonl` | 60 entries, each `{scenarioId, persona, question, answer, expectedOutcome, grounding}` |
| `reports/judge-calibration.md` | calibration report |
| `runs/latest/judge-cache.json` | content-hash verdict cache (live judges) |

## Offline vs live

Offline mode is the default and needs no API keys: the mock judge scores at
$0 real cost. Live mode (`claude` / `openai`) is opt-in and fails loudly
without keys via `requireLiveKey`.
